# 정육단 창업 문의 페이지

정육단 프랜차이즈 창업 상담용 원페이지 랜딩 사이트입니다. 빌드 도구 없이 순수 HTML/CSS/JS로만 만들어져 있습니다.

## 폴더 구조

```
├── index.html        페이지 전체 구조
├── css/style.css     스타일 (블랙 & 딥레드 톤, 반응형)
├── js/main.js        스크롤 등장 효과, 카운터, 폼 검증·전송
├── api/inquiry.js    문의 접수 → 이메일 전송 (서버리스 함수)
├── images/           매장 사진 (현재는 자리표시 SVG)
└── vercel.json       Vercel 배포 설정
```

> **캐시 주의**: `index.html`에서 CSS/JS를 `?v=2` 형태로 불러옵니다.
> 스타일이나 스크립트를 수정하면 이 숫자를 올려야 재방문자에게도 바로 반영됩니다.

### 매장 사진 교체 방법

`images/store-01.svg` ~ `store-10.svg`는 실제 사진이 없어 임시로 넣어둔 자리표시 이미지입니다.
실제 사진을 준비하시면 `images/` 폴더에 넣고 `index.html`의 해당 `<img src="...">` 경로만 바꾸면 됩니다.

## 페이지 구성

1. 히어로 — "로스율 0%, 뜯어서 서빙하는 고깃집" + 대표 영상
2. 브랜드 — 올바른 고기를 믿고 사는 시스템, 패밀리 프랜차이즈, 100년 가게
3. 왜 정육단인가 — 원팩 시스템 / 독점 메뉴 / 소주 1,000원 마케팅
4. 운영 시스템 — HACCP 공장, 커팅 설비, 3일 1회 물류, 발주 가이드, 비용 비교표
5. 메뉴 경쟁력 — 오징어 꽃삼겹, 숙성 삼겹살, 진생베리 숙성, 사이드
6. 소주 1,000원 — 절감 → 재투자 → 결과의 마케팅 전략, 점주 선택 사항임을 명시
7. 수익 구조 — 본점 매출·순마진율·객단가 + 인싸맨 영상
8. 매장 연혁 — 본점 포함 10개 매장 (오픈 순)
9. 상권 정책 — 1구 1점, 인재상, 인테리어 콘셉트
10. 창업 비용 / 가맹 절차 / FAQ / 창업 상담 폼

## 배포

Vercel에 GitHub 저장소가 연결되어 있으며, `main` 브랜치에 push하면 자동으로 배포됩니다.

## 문의 폼 이메일 설정 (필수)

문의 폼은 `api/inquiry.js` 서버리스 함수를 통해 Resend로 메일을 보냅니다.
**환경변수를 설정하기 전까지는 문의가 전송되지 않습니다.**

### 1. Resend 가입 및 API 키 발급

1. https://resend.com 에서 가입합니다.
2. API Keys → Create API Key → 권한은 `Sending access`면 충분합니다.
3. 발급된 키(`re_`로 시작)를 복사합니다. **이 키는 저장소에 절대 커밋하지 마세요.**

### 2. Vercel에 환경변수 등록

Vercel 프로젝트 → Settings → Environment Variables에서 추가합니다.

| 이름 | 값 | 필수 |
|---|---|---|
| `RESEND_API_KEY` | 발급받은 `re_...` 키 | 필수 |
| `INQUIRY_TO` | 문의를 받을 이메일. 쉼표로 여러 명 가능 | 필수 |
| `INQUIRY_FROM` | 보내는 사람 주소 | 선택 |

등록 후 **재배포해야 적용됩니다** (Deployments → 최신 배포 → Redeploy).

### 3. 보내는 주소에 대하여

- `INQUIRY_FROM`을 비워두면 Resend 테스트 주소(`onboarding@resend.dev`)로 발송됩니다.
  이 경우 **Resend 계정에 등록한 본인 이메일로만 수신**할 수 있습니다.
  즉 `INQUIRY_TO`는 Resend 가입 시 사용한 이메일과 같아야 합니다.
- 회사 도메인(예: `franchise@jungyukdan.co.kr`)으로 받거나 여러 명에게 보내려면
  Resend에서 도메인 인증(DNS에 DKIM/SPF 레코드 추가)을 마친 뒤
  `INQUIRY_FROM`을 `정육단 <franchise@도메인>` 형태로 설정하세요.

### 4. 확인

배포된 사이트에서 폼을 실제로 한 번 제출해 메일이 도착하는지 확인하세요.
실패 시 Vercel 대시보드 → Deployments → Functions 로그에서 원인을 볼 수 있습니다.

### 문제 해결

폼 제출 시 **502 오류**가 나면 함수는 정상 실행됐지만 Resend가 발송을 거부한 것입니다.
Vercel 대시보드 → 프로젝트 → **Logs**(또는 Deployments → 해당 배포 → Functions)에서
`Resend 전송 실패` 로그를 찾으면 **추정 원인과 조치 방법**이 한국어로 적혀 있습니다.

가장 흔한 원인은 다음과 같습니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 502 (오류 403), 로그에 `only send testing emails to your own` | 테스트 발신 주소는 Resend **가입 이메일로만** 발송 가능 | `INQUIRY_TO`를 Resend 가입 이메일과 똑같이 맞추거나, 도메인 인증 후 `INQUIRY_FROM` 설정 |
| 502 (오류 403), 로그에 `not verified` | `INQUIRY_FROM` 도메인이 미인증 | Resend → Domains에서 DNS 레코드 등록 후 인증 |
| 502 (오류 401) | API 키가 잘못됨 | 키 재발급 후 `RESEND_API_KEY` 갱신 → **재배포** |
| 500 | 환경변수 자체가 없음 | `RESEND_API_KEY`, `INQUIRY_TO` 등록 → **재배포** |

> 환경변수는 등록만으로 적용되지 않습니다. 반드시 **재배포**해야 합니다.

### 스팸 대응

`company`라는 숨김 필드(허니팟)를 두어 자동 봇 제출을 걸러냅니다.
사람에게는 보이지 않으며, 값이 채워져 오면 메일을 보내지 않고 성공 응답만 돌려줍니다.
문의량이 많아 스팸이 늘어나면 Cloudflare Turnstile 등 캡차 추가를 검토하세요.

### 매장 연혁 관련 확인 필요

- 매장별 지역 표기는 **매장명에서 유추한 것**입니다 (예: 화명점 → 부산 화명동). 실제 주소로 검증이 필요합니다.
- 상권 정책 섹션에 "1개 구에 1개 지점"을 명시했는데, 화명점과 덕천점은 둘 다 부산 북구에 해당할 수 있습니다.
  같은 구에 2개 지점이 맞다면 정책 문구를 조정하거나 예외 사유를 함께 안내하는 편이 좋습니다.
- 매장 연혁 섹션 하단의 "남은 자리 90곳"은 100개 - 10개로 계산한 값입니다. 계약 완료분이 따로 있다면 수정이 필요합니다.

### 매출 표기 관련 주의

수익 구조 섹션의 수치(본점 월매출 1억~1.3억원, 순마진율 30~32%, 객단가 8만원선)는 **본사 직영 본점 기준**으로 표기하고, 가맹점 매출을 보장하지 않는다는 문구를 함께 넣어두었습니다. 가맹사업법상 예상매출액 관련 정보는 서면(예상매출액 산정서) 제공 의무가 있으므로, 홍보를 본격적으로 시작하기 전 법무 검토를 권장합니다.
